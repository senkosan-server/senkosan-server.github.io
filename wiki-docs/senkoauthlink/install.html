    Установка SenkoAuthLink-Velocity¶

    Что нужно¶

    Требование Значение
    Прокси Velocity, собран против API 3.4.0-SNAPSHOT
    Java 17 или новее (сборка идёт на JDK 21, но release выставлен в 17)
    Банка плагина SenkoAuthLink-Velocity.jar
    Банка API SAL-API.jar - нужна, даже если другие плагины её не используют

    Обе банки кладутся в plugins прокси. Своих модов игрокам ставить не нужно, всё происходит на прокси.

    Почему нужны обе банки¶

    В velocity-plugin.json основной банки зависимость от API помечена как необязательная:

    "dependencies":[{"id":"senkoauthlinkapi-velosity","optional":true}]

    На практике SAL-API.jar всё равно обязательна. Основной плагин при старте вызывает SenkoAuthLinkProvider.setInstance(...), а этот класс лежит именно в API-банке. Без неё Velocity загрузит плагин, а на инициализации он упадёт с NoClassDefFoundError - команды не появятся, конфиг не создастся. Если такое случилось, смотрите Проблемы и решения.

    Порядок установки¶

    1. Положить в plugins обе банки: SenkoAuthLink-Velocity.jar и SAL-API.jar.
    2. Запустить прокси. Плагин создаст plugins/senkoauhlink-velosity/ с config.yml, базой database.db и папкой lang.
    3. Проверить, что плагины загрузились:
    /velocity plugins
    1. Разрешить игрокам заходить и авторизовываться: до входа чат и команды закрыты, работают только /register, /login и несколько служебных (раздел Команды и права).

    Если на прокси есть сервер-воронка, а не только игровые серверы, укажите его имя в auth.gate-server - тогда неавторизованных игроков будет отправлять туда, а не держать на прокси.

    Проверка после настройки¶

    • зайти на прокси новым ником и выполнить /register пароль пароль - должен прийти ответ Регистрация успешна;
    • перезайти и выполнить /login пароль - должен прийти ответ Авторизация успешна;
    • до входа попробовать написать в чат и выполнить любую команду, например /help, - плагин должен отклонить их.

    Сборка из исходников¶

    Проект собирается как Gradle-композит из двух модулей: папка с settings.gradle, где подключены SenkoAuthLink-Velocity и SenkoAuthLinkAPI-Velocity.

    ./gradlew :SenkoAuthLink-Velocity:shadowJar
./gradlew :SenkoAuthLinkAPI-Velocity:jar

    Готовые банки появятся в build/libs каждого модуля: SenkoAuthLink-Velocity.jar и SenkoAuthLinkAPI-Velosity-1.0-SNAPSHOT.jar. Вторую нужно переименовать в SAL-API.jar - именно под таким именем её копирует задача copyToServer и под таким именем она лежит на тестовом сервере.

    Две вещи, о которых стоит знать до сборки:

    • не запускайте просто ./gradlew build. Задача build зависит от copyToServer, а она копирует банку в жёстко прописанный путь C:\Users\<вы>\Desktop\Server Senko\Vel\plugins. На другой машине Gradle создаст эту папку или упадёт. Нужны именно shadowJar и jar, как выше;
    • в исходниках нет velocity-plugin.json. Ни в src/main/resources, ни в задании, которое его генерирует, - такого задания в build.gradle нет вообще. Файл есть только в собранных банках и в папке build. После ./gradlew clean shadowJar банка получится без описания плагина, и Velocity её не загрузит.

    Чтобы собрать рабочую банку, создайте src/main/resources/velocity-plugin.json с тем содержимым, что лежит в готовой банке:

    {"id":"senkoauhlink-velosity","name":"SenkoAUHLink-Velocity","version":"1.0-SNAPSHOT","description":"Registration, authentication, Discord linking and premium verification.","authors":["SenkoSan"],"dependencies":[{"id":"senkoauthlinkapi-velosity","optional":true}],"main":"com.senkoauhlink.senkoAUHLinkVelosity.SenkoAUHLinkVelosity"}

    Для API-банки файл нужен в SenkoAuthLinkAPI-Velocity/src/main/resources/velocity-plugin.json - у этого модуля папки resources нет вообще:

    {"id":"senkoauthlinkapi-velosity","name":"SenkoAuthLinkAPI-Velocity","version":"1.0-SNAPSHOT","description":"SenkoAuthLink API: предоставляет виртуальный лимбо (на базе LimboAPI) и интерфейсы авторизации.","authors":[],"dependencies":[],"main":"com.senkoauhlink.senkoAuthLinkAPIVelocity.SenkoAuthLinkAPIVelocity"}

    Значение version в обоих файлах собирается из версии Gradle-проекта: в src/main/templates лежит BuildConstants.java с "${version}", который подставляет шаблон до компиляции. Править его руками не нужно, но после clean он тоже создаётся заново задачей generateTemplates.

    Ещё две детали сборки:

    • Java: gradle.properties указывает org.gradle.java.home=C:/Program Files/Java/jdk-21. На другой машине путь нужно поменять или убрать;
    • вес банки: в src/main/resources/mapping/ лежит 14 файлов от LimboAPI, один из них - colors_main_map размером ровно 16 МиБ. Они попадают в банку целиком, хотя код плагина их не читает. Готовая банка из build/libs весит около 30 МБ.
