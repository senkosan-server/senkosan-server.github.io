    Хранилище и сообщения SenkoAuthLink-Velocity¶

    Файлы¶

    Всё лежит в папке plugins/senkoauhlink-velosity/:

    Файл Что это
    config.yml конфиг, ключи в разделе Основной конфиг
    database.db база SQLite с аккаунтами, кодами привязки и банами
    database.db-wal, database.db-shm служебные файлы журнала SQLite
    lang/ru.yml, lang/en.yml сообщения

    Папка lang и база создаются при первом запуске. Файлы переводов копируются из банки, только если их ещё нет, поэтому правки руками не перетираются. Если удалить lang/ru.yml, при следующем старте он вернётся из банки.

    База¶

    Одна база SQLite, три таблицы. Кеши, кулдауны и счётчики попыток в ней не хранятся - они в памяти.

    players¶

    Колонка Тип Что значит
    username TEXT, ключ ник, как его видит Velocity
    uuid TEXT UUID игрока на момент регистрации
    password_hash TEXT bcrypt, стоимость 10
    premium INTEGER привязан ли лицензионный ник
    premium_uuid TEXT id аккаунта с лицензии, если привязан
    discord_id TEXT Discord ID привязки, пусто - не привязан
    lang TEXT язык игрока, ru или en, пусто - язык по умолчанию
    two_factor INTEGER включено ли подтверждение входа
    registered_at INTEGER время регистрации, миллисекунды
    last_login_at INTEGER время последнего успешного входа, миллисекунды
    last_ip TEXT адрес последнего успешного входа

    Ключ - ник, а не UUID. Смена ника игроком означает другой аккаунт, а UUID в базе остаётся от старой регистрации.

    pending_links¶

    Колонка Что значит
    code код привязки, ключ
    username ник, для которого выдан код
    created_at когда выдан
    expires_at когда истечёт

    У одного игрока одновременно может быть только один код: новый удаляет старый. Использованные и истёкшие коды удаляются задачей раз в минуту.

    bans¶

    Колонка Что значит
    username ник, ключ
    reason причина, показывается при отключении
    banned_at время бана
    expires_at время окончания; ноль или меньше - навсегда

    Баны пишет только Discord-бот, ручной команды бана в игре нет. Истёкший бан удаляется сам при следующей попытке входа. Вечность определяется значением expires_at <= 0, а не отдельным флагом.

    Копия базы¶

    Плагин открывает базу в режиме WAL и не закрывает соединение при остановке прокси: вызова close() в коде нет, ProxyShutdownEvent только гасит бота Discord. Из-за этого копировать базу нужно так:

    1. остановить прокси;
    2. скопировать database.db вместе с database.db-wal и database.db-shm, если они есть;
    3. вернуть файлы на место и запустить прокси.

    Копировать один database.db во время работы прокси рискованно: последние изменения лежат в журнале. Перенос на другой прокси делайте на остановленном прокси.

    Сообщения¶

    Тексты лежат в lang/ru.yml и lang/en.yml в формате MiniMessage: теги <red>, <gray>, <yellow>, <aqua>, <click:run_command:...>, <hover:show_text:...>, <gradient:...> работают как есть.

    Правила подстановки:

    • prefix добавляется в начало каждого сообщения, кроме самого ключа prefix. В ru.yml это <gradient:#43cea2:#185a9d>SenkoAUH</gradient> <gray>»</gray>;
    • {имя} подставляют значения: {player}, {attempts}, {seconds}, {min}, {max}, {reason}, {until}, {code}, {command}, {discord}, {count}, {online}, {lang};
    • язык берётся у игрока из базы, а если там пусто - из language в конфиге;
    • время (например, until в бане) выводится в формате дд.ММ.гггг ЧЧ:мм.

    Группы ключей¶

    Группа О чём
    gate ответы на закрытый чат и команды
    welcome первые сообщения при входе, включая подсказки про лицензию
    login-timeout, ip-limit тексты отключений по таймеру и по лимиту IP
    ban тексты банов, включая баны через Discord
    register, login, logout, changepw, lang обычные команды игрока
    premium привязка лицензии
    twofa подтверждение входа
    link, unlink привязка Discord
    discord тексты и подписи для сообщений бота
    admin ответы /senkoa
    common общее и список команд

    Ключ premium.need-login в обоих файлах есть, но код его не использует - на этот ключ можно не смотреть.

    Пример сообщения¶

    twofa.request: "<yellow>Подтверди вход!</yellow> <gray>Это новое устройство/IP.</gray> <gray>Нажми:</gray> <yellow><click:run_command:/senko 2fa confirm><hover:show_text:'<gray>Подтвердить вход</gray>'>[ПОДТВЕРДИТЬ ВХОД]</hover></click></yellow> <gray>или подтверди в Discord.</gray>"

    Правка lang/ru.yml подхватывается командой /senkoa reload или перезапуском прокси.
