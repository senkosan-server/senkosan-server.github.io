    Справочник API SenkoAuthLinkAPI-Velocity¶

    Всё в пакете com.senkoauhlink.senkoAuthLinkAPI.api. Единая точка входа - SenkoAuthLinkProvider.get().

    Провайдер¶

    SenkoAuthLinkProvider - синглтон с тринадцатью геттерами. Экземпляр собирает основной плагин и кладёт в статическое поле:

    public static SenkoAuthLinkProvider get();
public static void setInstance(SenkoAuthLinkProvider provider);
public static Builder builder();
    Геттер Тип Кто кладёт в провайдер
    getAuthManager() api.auth.AuthManager да
    getAuthService() api.auth.AuthService да
    getSessionManager() api.auth.SessionManager да
    getPlayerRepository() api.storage.PlayerRepository да
    getBanService() api.storage.BanService да
    getLinkRepository() api.storage.LinkRepository да
    getDiscordManager() api.discord.DiscordManager да
    getPremiumChecker() api.auth.PremiumChecker да
    getEventManager() api.event.EventManager да
    getTwoFactorService() api.auth.TwoFactorService нет, всегда null
    getLinkService() api.auth.LinkService нет, всегда null
    getLimboGate() api.auth.LimboGate нет, всегда null
    getPremiumService() api.auth.PremiumService нет, всегда null

    builder() требует заполнить только шесть первых полей, остальные можно не передавать - поэтому четыре сервиса выше и остаются null. Что с ними делать, написано в Проблемы и решения.

    Авторизация¶

    AuthManager¶

    boolean isAuthed(Player player);
void handlePreLogin(PreLoginEvent event);
void handleLogin(Player player);
void onDisconnect(Player player);
void purgePremiumAuth(long now);
void purgeTwoFactor(long now);

    Из этих методов стороннему плагину полезен только isAuthed. Остальные - обработчики событий Velocity, которые основной плагин вызывает сам; вызывать их из своего кода не нужно.

    AuthService¶

    void register(Player player, String password1, String password2);
void login(Player player, String password);
void logout(Player player);
void changePassword(Player player, String oldPassword, String newPassword1, String newPassword2);
void setLang(Player player, String lang);

    Реализация в основном плагине - это тот же AuthManager, который обслуживает команды. Через API можно зарегистрировать или авторизовать игрока программно. Ответов эти методы не возвращают: результат приходит игроку в чат.

    Все три интерфейса реализует один класс основного плагина, поэтому фактически это один и тот же объект. Методы синхронизированы, исключения при ошибках базы бросаются как RuntimeException.

    Осторожно с create(PlayerAccount): модель требует непустые username, uuid и passwordHash, иначе будет IllegalStateException. Хеш пароля нужно передавать уже готовым bcrypt - в API нет метода, который его посчитает.

    start и setTwoFactorHandler основной плагин вызывает сам, повторный вызов будет лишним. Обращения к Discord, когда isEnabled() возвращает false, ничего не делают.

    Модели¶

    Класс Что это
    AuthState enum: NEW, PENDING_REGISTER, PENDING_LOGIN, PENDING_2FA, AUTHENTICATED
    PlayerAccount неизменяемый аккаунт, собирается через builder(): ник, uuid, хеш пароля, флаг и uuid лицензии, Discord ID, флаг 2FA, язык, времена регистрации и последнего входа, прошлый IP
    PlayerSession снимок сессии: uuid, ник, IP, статус, число попыток, язык, запрошенный сервер, время запроса. Есть isAuthenticated() и isPendingAuth()
    PremiumInfo record из трёх полей: known, premium, uuid. known означает, что ответ Mojang получен и разобран, а не что ник лицензионный
    Ban ник, причина, время бана, время окончания. isPermanent() и isExpired() считают вечность как expiresAt <= 0
    PendingLink код, ник, когда выдан, когда истечёт, и isExpired()

    События¶

    Классы событий лежат в api.event: AuthEvent, LoginEvent, RegisterEvent, LogoutEvent, DisconnectEvent, BanEvent, LinkEvent, TwoFactorEvent. У всех одинаковая форма - конструктор с Player и данными, геттеры без сеттеров.

    EventManager - минимальный диспетчер на ConcurrentHashMap:

    <T> void register(Class<T> eventClass, Consumer<T> handler);
<T> void unregister(Class<T> eventClass, Consumer<T> handler);
<T> void fire(T event);

    Важно: основной плагин не вызывает fire(). Ни одного вызова в его коде нет, события не отправляются ни при входе, ни при бане, ни при привязке. Подписка через register - рабочая, но придёт пусто. Подробности в Проблемы и решения.

    AuthConfig¶

    api.config.AuthConfig - неизменяемый снимок настроек с билдером и 28 полями: требование регистрации, длины пароля, число попыток, таймеры, серверы начального и вороначного, лимиты IP, префикс IPv6, премиум, Discord и язык.

    Значения по умолчанию у него не совпадают с config.yml основного плагина:

    Поле В config.yml В AuthConfig
    minPasswordLength 6 4
    maxPlayersPerIp 0 3
    ipLimitExemptAuth false true
    premiumEnabled true false
    premiumForceOnlineAuth true false
    premiumAuthFallbackMinutes 15 10
    discordLinkCodeLength 8 6

    И главное: плагин этот класс не собирает. В его коде нет ни одного упоминания AuthConfig, а в провайдере его нет среди геттеров. Считать по нему реальные настройки нельзя, читайте config.yml.
