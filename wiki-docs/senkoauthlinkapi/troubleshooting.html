    Проблемы и решения SenkoAuthLinkAPI-Velocity¶

    Плагин не появляется в списке¶

    Банка собрана из исходников и не загружается. В модуле нет папки src/main/resources, а значит нет и velocity-plugin.json. В build.gradle нет задания, которое его создаёт. В собранной ранее банке файл есть, в исходниках его нет, поэтому после ./gradlew clean jar получится банка, которую Velocity не считает плагином.

    Чтобы починить, создайте SenkoAuthLinkAPI-Velocity/src/main/resources/velocity-plugin.json:

    {"id":"senkoauthlinkapi-velosity","name":"SenkoAuthLinkAPI-Velocity","version":"1.0-SNAPSHOT","description":"SenkoAuthLink API: предоставляет виртуальный лимбо (на базе LimboAPI) и интерфейсы авторизации.","authors":[],"dependencies":[],"main":"com.senkoauhlink.senkoAuthLinkAPIVelocity.SenkoAuthLinkAPIVelocity"}

    Файл называется не SAL-API.jar. Сборка даёт SenkoAuthLinkAPI-Velocity-1.0-SNAPSHOT.jar. Переименование в SAL-API.jar делает только задача copyToServer, а её имя файла нигде не проверяется: для Velocity подойдёт любое имя, важен id внутри банки.

    Основной плагин не грузится, а модуль грузится. Так и должно быть: основной плагин падает с NoClassDefFoundError, если банки API нет (раздел Проблемы и решения основного плагина).

    События не приходят¶

    Подписка через EventManager.register(...) не выдаёт ошибок, но обработчики не вызываются никогда. В коде основного плагина нет ни одного вызова fire() - он создаёт EventManager, отдаёт его провайдеру и на этом останавливается. Ни вход, ни регистрация, ни бан, ни привязка Discord событий не порождают.

    Что можно сделать:

    • не рассчитывать на события API: проверять состояние по getAuthManager().isAuthed(player) или по getPlayerRepository().findByUsername(nick), когда реально понадобится;
    • подписаться на события Velocity (PostLoginEvent, PlayerChooseInitialServerEvent, DisconnectEvent) и сверяться с провайдером - это работает;
    • свой код в основном плагине, который вызывает fire(), править придётся в обоих проектах.

    Часть провайдера возвращает null¶

    getTwoFactorService(), getLinkService(), getLimboGate() и getPremiumService() всегда возвращают null: основной плагин их не заполняет, а билдер требует только шесть первых полей. Вызов любого метода через эти геттеры даст NullPointerException.

    Чем заменить:

    Геттер Рабочая замена
    getPremiumService() getPremiumChecker() плюс getAuthService() для привязки
    getLinkService() getLinkRepository() плюс getAuthService()
    getTwoFactorService() своей логикой: getPlayerRepository().setTwoFactor(nick, true) и проверкой через getSessionManager()
    getLimboGate() своей логикой на PlayerChooseInitialServerEvent и ServerPreConnectEvent

    Проверять надо сам факт: SenkoAuthLinkProvider.get() тоже возвращает null, если основной плагин не загрузился.

    AuthConfig не соответствует настройкам¶

    Класс api.config.AuthConfig есть, но плагин его не собирает: упоминаний AuthConfig в коде основного плагина нет, и в провайдере геттера для него тоже нет. Если создать AuthConfig самому через builder(), получится набор значений по умолчанию из API, а не реальные значения из config.yml. Часть из них отличается, часть - нет, поэтому сверяться с конфигом придётся вручную.

    Рабочий способ узнать настоящие настройки - прочитать plugins/senkoauhlink-velosity/config.yml.

    Содержимое банки не совпадает с исходниками¶

    Готовая SAL-API.jar в build/libs заметно больше, чем может собрать текущий build.gradle:

    • в ней есть классы LimboAPI (net.elytrium.limboapi.*) и его данные mapping/, хотя в build.gradle модуля нет ни зависимости на LimboAPI, ни папки с его исходниками;
    • описание плагина обещает виртуальный лимбо на базе LimboAPI, но сам модуль лимбо не реализует: в нём есть только интерфейс LimboGate, а реализация лежит в основном плагине и LimboAPI не вызывает.

    Практический вывод: пересобрать банку и получить её нынешний вид нельзя, пока в модуль не вернут зависимость на LimboAPI. Для работы SenkoAuthLink-Velocity это не нужно: он использует только интерфейсы, а свой limbo держит игрока на прокси без LimboAPI.

    Сборка¶

    ./gradlew build лезет на локальный диск. У задачи build есть зависимость от copyToServer, а она копирует банку в C:\Users\<вы>\Desktop\Server Senko\Vel\plugins. Собирайте ./gradlew :SenkoAuthLinkAPI-Velocity:jar.

    Gradle не находит Java. В gradle.properties модуля прописан org.gradle.java.home=C:/Program Files/Java/jdk-21.

    publish ничего не отправляет в интернет. Публикация идёт в локальный репозиторий build/repo. Готовый pom указывает адрес https://github.com/senkoan/senkoauthlinkapi-velosity, но в .git/config модуля remote не настроен, а в .git остались только пустые ссылки refs/remotes/origin/HEAD - следы клона, у которого remote убрали. Так что ссылка из pom сейчас нерабочая.

    README.md пустой. В нём одна строка # SenkoAuthLinkAPI. Описания API в проекте нет, зато есть этот раздел вики.

    Мелочи, о которых стоит знать¶

    • SenkoAuthLinkAPIVelocity.get() отдаёт загруженный экземпляр модуля, из него можно взять getLogger() и getProxy();
    • версия везде 1.0-SNAPSHOT, и в банке, и в pom, и в BuildConstants, который генерируется шаблоном src/main/templates;
    • лицензия в pom - MIT, разработчик - SenkoSan, но файла LICENSE в модуле нет.
